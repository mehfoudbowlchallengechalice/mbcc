Deploy MBCC using Google Cloud Console

1. Open https://console.cloud.google.com/?project=project-72f15f51-cfef-4c90-b6e
2. Click Activate Cloud Shell (>_) in the upper-right toolbar.
3. Use the Cloud Shell three-dot menu > Upload and upload mbcc-cloudrun.zip
   to your Cloud Shell home directory.
4. Paste these commands into Cloud Shell:

   unzip -o ~/mbcc-cloudrun.zip -d ~/mbcc-cloudrun
   cd ~/mbcc-cloudrun
   bash cloudrun/update-live-source.sh

5. If Google asks to authorize Cloud Shell, review and authorize it yourself.
6. Keep the tab open while Google builds and deploys the service.
7. The script prints your app connection URL and checks the real spreadsheet
   response. If an error occurs, share the error text in the chat.

This updates the existing mbcc-api service using its existing reader/build identities.
It preserves container-only environment variables, including MBCC_SUB_KEYWORD
and MBCC_COMBINED_KEYWORD, plus all MBCC_[NAME]_KEYWORD player variables.
Set their values directly in Cloud Run; do not put
the values in env.yaml or upload them in the ZIP. The apps send masked entries
in a request header, and the API alone decides which group to return.
Add a distinct player keyword for each of the nine main-group roster names,
such as MBCC_CHRISTOPHER_KEYWORD and MBCC_NICHOLAS_KEYWORD. One entry selects
that player's picks, while everyone remains visible. Correct final picks have
a solid green underline; incorrect final picks have a dotted gray underline.
Pending picks are bold without a result line. Unknown entries show ordinary
main-group results. Deploy the API first, then publish Streamlit and rebuild
the iPhone app to enable these highlights.
Games come from live_scores_and_games, and original tabs supply verification references.
The configuration enables that source and labels the season MBCC 15 · 2026–27.
Imported games and scores stay unverified until the first successful automatic check.
The update script checks the deployed source and prints both verification counts.
Existing overall summary/history tabs remain in the challenge workbook.
The new all-time playoff table reads rows 1–3 of playoff_picks in the separate
history workbook (1Iwl1WEzLEXu05ZtFcfZovWwQsECNy8LH3II760C-w2E).
The reader service account needs Viewer access to that workbook too.
Today's Update is enabled and reads the todays_update tab in the challenge workbook.
The deployment check prints the number of published blog posts. Newest posts
appear first; earlier posts remain below them with their dates and video links.

The Google account running these steps needs permission to deploy source updates
using the existing service accounts. For a brand-new service, use cloudrun/deploy.sh
instead; it performs the original API/IAM setup.
